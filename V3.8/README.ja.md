## 1. モデル概要

MoziAI-27B-3.8 は、中国の金融分野で著名なインフルエンサーである陳雨墨（チェン・ユーモー）チームが開発した、ローカルデプロイ向けのオープンソース多モーダルAI大規模モデルです。オープンソースのベースモデル **Qwen3.8-27B**（Dense 27B アーキテクチャ、MIT ライセンス）を基盤に、チーム独自開発の金融データ＋金融領域能力＋動的七次元思考体系＋エージェントLOOP反省反復メカニズム＋MoziSmartBitハイブリッド量子化アルゴリズムを組み合わせて開発されました。本モデルは個人・企業のローカルデプロイのハードルを下げ、**商用無料**を許諾しています。コンシューマー向けGPUでローカルデプロイが可能であり、クラウドのトークンコストを大幅に節約し、7×24時間のトークン自由を実現するとともに、ローカルデータのプライバシーとセキュリティを確保します。

## 2. モデルの特徴

### 🧠 動的七次元思考体系

MoziAI 独自開発のコア推論フレームワークです。あらゆるタスクに対して、モデルはまず **moziAI-Think** マーカーを出力し、タスクの複雑さに応じて構造化された思考を動的に展開します：

| レベル | 適用シーン | 代表的なタスク | 展開する次元 |
| --- | --- | --- | --- |
| **Level 0** | 簡単なQ&A | 用語解説、事実検索、翻訳、要約 | ①タスク理解 ⑤リソース要件（2次元で即答） |
| **Level 1** | 分析・診断 | 市場調査、文書作成、データ分析、レポート解釈、戦略評価 | ①②③⑤⑥ の5次元評価 |
| **Level 2** | 複雑な開発/戦略 | コード開発、アーキテクチャ設計、クオンツ戦略開発、複数ステップのワークフロー、システム設計 | ①②③④⑤⑥⑦ の全7次元による深い推演 |

> 七次元：①タスク理解 ②複雑度評価 ③依存関係 ④リスク評価 ⑤リソース要件 ⑥受入基準 ⑦実行戦略

### 🔄 エージェント LOOP 反復メカニズム

複雑なタスクは自動的に **moziAI-Loop** 反復モードに入ります：**第1ラウンド実行＋評価 → 第2ラウンド調整＋検証**により、自己検証を経た出力のみが最終回答として提供されます。モデルは熟練エンジニアのように「問題の分解 → プランの評価 → 実行 → 振り返り → 最適化」を実行し、複雑なタスクの正確性と実行可能性を大幅に向上させます。簡単なQ&AやタスクではLoopは自動的にオフになります。

### 📦 MoziSmartBit スマート量子化

独自開発の階層型スマート量子化により、270億パラメータのDenseモデルを約 **13.7 GB** に圧縮します。通常のQ4_K_M（約17 GB）と比較して約3.3 GB（約20%）小さく、FP16の **約99%** の精度を維持します。従来の量子化はすべてのレイヤーに統一精度を適用しますが、MoziSmartBitはDenseモデルの構造的特徴に応じたインテリジェントな差別化戦略を採用し、Q4_K_Mよりも優れた精度を実現します。

### 💰 金融特化領域へのフォーカス

金融Q&A、クオンツプログラミング、ツール呼び出しに向けた深い最適化が施されています。金融分野ではモデルの幻覚（ハルシネーション）に対する許容度が極めて低い中、MoziAIはこの分野において同規模の汎用モデルを大幅に上回る性能を発揮します。

### 🌐 その他の特徴

- **多言語対応**：201の言語・方言に対応し、中国語能力を特に最適化
- **汎用プログラミング**：フルスタック開発、コードデバッグ、アーキテクチャ設計。Python/JS/TS/Go/Rust をカバー
- **文章作成**：リサーチレポート、分析記事、技術ドキュメント、クリエイティブコンテンツなど多ジャンルの高品質な文章作成
- **視覚理解**：マルチモーダルな視覚機能を備え、ローカルでのスクリーンショットや画像内容の理解に対応
- **マルチフレームワーク対応**：llama.cpp / Ollama / LM Studio / Jan
- **マルチエージェント対応**：OpenClaw / Hermes / Cursor / Claude Code / Codex など。ネイティブなツール呼び出しとマルチターンのタスクオーケストレーション

## 6. ⚡ クイックスタート（3 つのファイル = 100% 最高の推論能力を有効化）

> ⚠️ **重要ポイント**：MoziAIの最高の推論能力を引き出すには、**3つのファイルを同時にダウンロード**する必要があります——メインモデル、ビジョンプロジェクタ、チャットテンプレート。いずれか1つでも欠けると、対応する機能が失われます。

### 6.1 モデルファイルのダウンロード

HuggingFace / ModelScope で **V3.8 ディレクトリ内のすべてのファイル**をローカルの同一ディレクトリにダウンロードしてください：

```
V3.8/
├── moziAI-27B-MTP-V3.8-Q4_K_M-Qwen3.8-27B.gguf   ← 主模型（必选，13.7 GB）
└── chat-template-moziai-27B-V3.8.jinja         ← 聊天模板（必选，含七维思考+Loop指令）

mmproj/27B/
└── moziAI-27B-mmproj-BF16-V1.0.gguf            ← 视觉投影（必选，927 MB）
```

| ファイル | サイズ | 必須性 | 役割 |
| --- | --- | --- | --- |
| メインモデル `.gguf` | ~13.7 GB | **必須** | モデル重み、コアの推論能力 |
| ビジョンプロジェクタ `mmproj` | ~927 MB | **必須** | マルチモーダル視覚理解。未ロードの場合は画像能力が失われる |
| チャットテンプレート `.jinja` | わずか | **必須** | MoziAIのアイデンティティ＋七次元思考＋LOOPメカニズムの指示を注入 |

### 6.2 起動と利用

```bash
llama-server \
  -m ./moziAI-27B-MTP-V3.8-Q4_K_M-Qwen3.8-27B.gguf \
  --mmproj mmproj/27B/moziAI-27B-mmproj-BF16-V1.0.gguf \
  --chat-template-file V3.8/chat-template-moziai-27B-V3.8.jinja \
  -c 131072 -ngl 99 \
  --host 0.0.0.0 --port 8080
```

ブラウザで `http://localhost:8080` を開けば、すぐに会話を開始できます。完全な推奨パラメータは第9節を参照してください。

## 8. 起動コマンド

### 最小構成での起動（三点セット込み）

```bash
llama-server \
  -m ./moziAI-27B-MTP-V3.8-Q4_K_M-Qwen3.8-27B.gguf \
  --mmproj mmproj/27B/moziAI-27B-mmproj-BF16-V1.0.gguf \
  --chat-template-file V3.8/chat-template-moziai-27B-V3.8.jinja \
  -c 131072 -ngl 99 \
  --host 0.0.0.0 --port 8080
```

### 完全な推奨起動構成

```bash
llama-server \
  -m ./moziAI-27B-MTP-V3.8-Q4_K_M-Qwen3.8-27B.gguf \
  --mmproj mmproj/27B/moziAI-27B-mmproj-BF16-V1.0.gguf \
  --chat-template-file V3.8/chat-template-moziai-27B-V3.8.jinja \
  -c 131072 -ngl 99 -t 28 \
  --batch-size 1024 --ubatch-size 128 \
  --flash-attn auto \
  --cache-type-k q4_0 --cache-type-v q4_0 --kv-unified \
  --poll 0 \
  --reasoning auto --reasoning-budget 1024 --reasoning-format deepseek-legacy \
  --spec-type draft-mtp --spec-draft-n-max 2 --spec-draft-p-min 0.75 \
  --host 0.0.0.0 --port 8080 \
  --temp 0.6 --top-p 0.95 --top-k 20
```

> 💡 MTPを無効にする場合：`--spec-type draft-mtp` と関連パラメータを削除してください。速度は約30〜50%低下しますが、VRAM使用量は小さくなります。

## 9. 推奨推論パラメータ

llama.cpp 公式の推奨パラメータとローカルでの実測に基づく最適化（AMD Radeon AI PRO R9700 32GB）：

| パラメータ | 汎用チャット | コーディング/Agent | 説明 |
| --- | --- | --- | --- |
| temperature | 0.7 | 1.0 | 創造性と正確性のバランス |
| top\_p | 0.95 | 0.95 | 核サンプリングの閾値 |
| top\_k | 20 | 20 | トランケーションサンプリング |
| repeat\_penalty | 1.05 | 1.05 | 繰り返しペナルティ |
| context\_length | 262144 | 262144 | 128K の長いコンテキスト |
| reasoning | auto | auto | 推論チェーン（思考連鎖）を有効化 |
| reasoning\_budget | 400 | 400 | 推論予算トークン |
| reasoning\_format | deepseek-legacy | deepseek-legacy | 推論を独立したフィールドに出力 |
| **spec-type** | **draft-mtp** | **draft-mtp** | **MTP投機的復号（詳細は第11節）** |

> 💡 **思考モード**：`--reasoning auto` で有効化すると、モデルは内部推論を行ってから回答を出力します。`reasoning_budget` は最大思考トークン数を制御します（推奨400、100〜1000の範囲で調整可能）。

## 10. 量子化形式の比較

| 形式 | サイズ | 精度 | 説明 |
| --- | --- | --- | --- |
| FP16 オリジナル | ~54 GB | 100% | ロスレス。プロフェッショナル向けGPUが必要 |
| **MoziSmartBit（本モデル）** | **~13.7 GB** | **~99%** | **独自開発のスマート量子化。最高精度・最小サイズ** |
| Q4_K_M | ~17 GB | ~98% | GGUF標準 4bit |
| Q5_K_M | ~20 GB | ~99% | より高い精度 |
| Q6_K | ~23 GB | ~99.5% | ほぼロスレス |
| Q8_0 | ~31 GB | ~100% | ロスレス |

> MoziSmartBitは約99%の精度を維持しながら、27B Denseモデルを13.7 GB（圧縮率3.9倍）に圧縮します。Q4_K_Mより約20%小さく、コンシューマー向けGPUでのローカルデプロイに最適です。

## 11. MTP 投機的復号（重要な高速化機能）

本モデルにはMTP（Multi-Token Prediction）投機的復号レイヤーが内蔵されており、有効化すると推論速度が **1.5〜2倍** に向上します。これはQwen3.8アーキテクチャのネイティブ機能であり、MoziAIは完全なMTP重みを保持しています。

**原理**：モデルアーキテクチャには、メインモデルが検証する前に後続トークンを事前に推測する軽量な予測ヘッド（Draft Model）が追加で訓練されています。これによりforward回数が減少し、推論レイテンシが低下します。推測が誤っていた場合はメインモデルが修正するため、出力品質に悪影響はありません。

### 有効化パラメータ

```bash
--spec-type draft-mtp \
--spec-draft-n-max 2 \
--spec-draft-p-min 0.75
```

| パラメータ | 推奨値 | 説明 |
| --- | --- | --- |
| --spec-type | draft-mtp | MTP投機的復号を有効化 |
| --spec-draft-n-max | 2 | 毎回最大2トークンを推測（推奨値、受容率約80%） |
| --spec-draft-p-min | 0.75 | 最低受容確率の閾値（0.0〜1.0、大きいほど保守的） |

### パラメータ調整の推奨

| n-max | 受容率 | 適用シーン |
| --- | --- | --- |
| 1 | ~90% | 最も保守的。速度向上は最小 |
| **2** | **~80%** | **推奨：速度と正確性のバランス** |
| 3 | ~71% | 汎用シーン。速度向上が顕著 |
| 4-5 | ~60-65% | クリエイティブライティング、コード生成 |
| 6 | ~50-55% | プレーンテキストの長文出力（p-minの調整と併用が必要） |

## 12. VRAM構成（推奨）

| VRAM | 推奨構成 | 説明 |
| --- | --- | --- |
| 16 GB | コンテキストを64Kに削減、CPUオフロードが必要 | エントリークラス。例：RTX 4060 Ti |
| **20 GB** | **128Kフル構成、q4_0 KVキャッシュ** | **推奨構成**。例：RX 7900 XT / RTX 5070 Ti |
| 24 GB | 128Kフル構成、VRAMに十分な余裕 | RTX 4090 / RX 7900 XTX |
| 32 GB以上 | 128Kフル構成、最強の構成 | Radeon AI PRO R9700 / RTX 5090 |
| 128 GB 内蔵GPU | 128Kフル構成 | AMD Ryzen AI Max+ 395 / NVIDIA RTX Spark |

> 💡 コンテキストが長いほどVRAM使用量が増えます。OOMが発生した場合は `-c` パラメータを段階的に下げてください。`--fit on` を使用すると、llama.cppがVRAMに合わせてレイヤー数を自動調整します。NVIDIA / AMD / Intel 全ブランドのGPUに対応しています。
