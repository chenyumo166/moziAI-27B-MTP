## 1. Обзор модели

MoziAI-27B-3.8 — это локальная открытая мультимодальная ИИ-модель большого размера, разработанная командой Чэнь Юймо, известного китайского финансового эксперта, на основе открытой базовой модели **Qwen3.8-27B** (архитектура Dense 27B, лицензия MIT). Модель объединяет собственные разработки команды: финансовые данные + финансовые предметные возможности + динамическую семимерную систему мышления + итеративный механизм рефлексии агента LOOP + гибридный алгоритм квантования MoziSmartBit. Данная модель снижает порог локального развертывания для частных лиц и предприятий, разрешено **бесплатное коммерческое использование**, она может быть развернута локально на потребительских видеокартах, что значительно экономит затраты на облачные токены, обеспечивает свободу токенов 7×24 часа и гарантирует конфиденциальность и безопасность локальных данных.

## 2. Особенности модели

### 🧠 Динамическая семимерная система мышления

Собственная ключевая архитектура рассуждения MoziAI. При любой задаче модель сначала выводит маркер **moziAI-Think**, затем динамически разворачивает структурированное мышление в зависимости от сложности задачи:

| Уровень | Применимые сценарии | Типовые задачи | Разворачиваемые измерения |
| --- | --- | --- | --- |
| **Level 0** | Простые вопросы и ответы | Объяснение терминов, фактические запросы, перевод, резюме | ①Понимание задачи ⑤Потребность в ресурсах (быстрый ответ по двум измерениям) |
| **Level 1** | Анализ и диагностика | Маркетинговые исследования, написание текстов, анализ данных, интерпретация аналитических отчетов, оценка стратегий | ①②③⑤⑥ оценка по пяти измерениям |
| **Level 2** | Сложная разработка/стратегии | Разработка кода, проектирование архитектуры, разработка количественных стратегий, многошаговые рабочие процессы, проектирование систем | ①②③④⑤⑥⑦ полное развертывание по всем семи измерениям |

> Семь измерений: ①понимание задачи ②оценка сложности ③зависимости ④оценка рисков ⑤потребность в ресурсах ⑥критерии приемки ⑦стратегия выполнения

### 🔄 Итеративный механизм агента LOOP

Сложные задачи автоматически переходят в итеративный режим **moziAI-Loop**: **раунд 1 — выполнение + оценка → раунд 2 — корректировка + проверка**, что гарантирует прохождение выходных данных через самопроверку перед выдачей окончательного ответа. Модель, подобно опытному инженеру, выполняет цикл «разбить задачу → оценить решение → выполнить → отрефлексировать → оптимизировать», что значительно повышает точность и исполнимость сложных задач. Для простых вопросов и задач Loop автоматически отключается.

### 📦 Интеллектуальное квантование MoziSmartBit

Собственное многоуровневое интеллектуальное квантование: Dense-модель с 27 миллиардами параметров сжимается примерно до **13,7 ГБ**, что примерно на 3,3 ГБ (~20%) меньше, чем стандартный Q4_K_M (~17 ГБ), при сохранении **~99%** точности FP16. Традиционное квантование использует единую точность для всех слоев, тогда как MoziSmartBit применяет интеллектуальную дифференцированную стратегию с учетом особенностей архитектуры Dense-моделей, обеспечивая точность выше, чем у Q4_K_M.

### 💰 Фокус на финансовой вертикали

Глубокая оптимизация для финансовых вопросов и ответов, количественного программирования и вызова инструментов. Финансовая сфера крайне нетерпима к галлюцинациям моделей; MoziAI в этой области значительно превосходит универсальные модели аналогичного размера.

### 🌐 Прочие возможности

- **Многоязычная поддержка**: 201 язык и диалект, китайский язык оптимизирован особо
- **Универсальное программирование**: full-stack разработка, отладка кода, проектирование архитектуры; поддержка Python/JS/TS/Go/Rust
- **Написание статей**: качественное написание аналитических отчетов, аналитических статей, технической документации, творческого контента и других жанров
- **Визуальное понимание**: мультимодальное зрение, поддержка локального понимания содержимого скриншотов
- **Поддержка нескольких фреймворков**: llama.cpp / Ollama / LM Studio / Jan
- **Поддержка нескольких агентов**: OpenClaw / Hermes / Cursor / Claude Code / Codex и др., нативный вызов инструментов и оркестрация многораундовых задач

## 3. Примечания к обновлению версии

В данном обновлении версии в основном усилены: собственный режим рассуждения moziAI с динамическим семимерным мышлением + итерацией LOOP, что позволяет более интеллектуально распознавать сложность задач, повышает процент завершения сложных задач и улучшает способность «сначала подумать, потом сделать».

moziAI сохраняет активную частоту итеративных обновлений версий, чтобы не отставать от будущего развития искусственного интеллекта, и постоянно, с помощью собственных технологий, делает локальные ИИ-модели легковесными в развертывании и все более мощными.

## 6. ⚡ Быстрый старт (3 файла = 100% активация лучших возможностей инференса)

> ⚠️ **Ключевая подсказка**: лучшие возможности инференса MoziAI требуют **одновременной загрузки 3 файлов** — основной модели, визуального проектора и шаблона чата. Отсутствие любого из них приведет к потере соответствующей возможности.

### 6.1 Загрузка файлов модели

Загрузите **все файлы из каталога V3.8** на HuggingFace / ModelScope в одну локальную директорию:

```
V3.8/
├── moziAI-27B-3.8-Q4_K_M-Qwen3.8-27B.gguf   ← 主模型（必选，13.7 GB）
└── chat-template-moziai-27B-v38.jinja         ← 聊天模板（必选，含七维思考+Loop指令）

mmproj/27B/
└── moziAI-27B-mmproj-BF16-V1.0.gguf            ← 视觉投影（必选，927 MB）
```

| Файл | Размер | Обязательность | Назначение |
| --- | --- | --- | --- |
| Основная модель `.gguf` | ~13,7 ГБ | **Обязателен** | Веса модели, основные возможности инференса |
| Визуальный проектор `mmproj` | ~927 МБ | **Обязателен** | Мультимодальное визуальное понимание; без загрузки изображения не поддерживаются |
| Шаблон чата `.jinja` | Минимальный | **Обязателен** | Внедрение идентичности MoziAI + инструкций семимерного мышления + механизма LOOP |

### 6.2 Запуск и использование

```bash
llama-server \
  -m V3.8/moziAI-27B-3.8-Q4_K_M-Qwen3.8-27B.gguf \
  --mmproj mmproj/27B/moziAI-27B-mmproj-BF16-V1.0.gguf \
  --chat-template-file V3.8/chat-template-moziai-27B-v38.jinja \
  -c 131072 -ngl 99 \
  --host 0.0.0.0 --port 8080
```

Откройте `http://localhost:8080` в браузере, чтобы начать диалог. Полные рекомендуемые параметры см. в разделе 9.

## 8. Команды запуска

### Минимальный запуск (полный комплект из 3 файлов)

```bash
llama-server \
  -m V3.8/moziAI-27B-3.8-Q4_K_M-Qwen3.8-27B.gguf \
  --mmproj mmproj/27B/moziAI-27B-mmproj-BF16-V1.0.gguf \
  --chat-template-file V3.8/chat-template-moziai-27B-v38.jinja \
  -c 131072 -ngl 99 \
  --host 0.0.0.0 --port 8080
```

### Полный рекомендуемый запуск

```bash
llama-server \
  -m V3.8/moziAI-27B-3.8-Q4_K_M-Qwen3.8-27B.gguf \
  --mmproj mmproj/27B/moziAI-27B-mmproj-BF16-V1.0.gguf \
  --chat-template-file V3.8/chat-template-moziai-27B-v38.jinja \
  -c 131072 -ngl 99 -t 28 \
  --batch-size 1024 --ubatch-size 128 \
  --flash-attn auto \
  --cache-type-k q4_0 --cache-type-v q4_0 --kv-unified \
  --poll 0 \
  --reasoning auto --reasoning-budget 1024 --reasoning-format deepseek-legacy \
  --spec-type draft-mtp --spec-draft-n-max 2 --spec-draft-p-min 0.75 \
  --host 0.0.0.0 --port 8080 \
  --temp 0.6 --top-p 0.95 --top-k 20
```

> 💡 Отключение MTP: удалите `--spec-type draft-mtp` и связанные параметры — скорость снизится примерно на 30-50%, потребление видеопамяти уменьшится.

## 9. Рекомендуемые параметры инференса

На основе официальных рекомендуемых параметров llama.cpp и локальных измерений оптимизации (AMD Radeon AI PRO R9700 32GB):

| Параметр | Обычный чат | Кодирование/агент | Описание |
| --- | --- | --- | --- |
| temperature | 0.7 | 1.0 | Баланс креативности и точности |
| top\_p | 0.95 | 0.95 | Порог ядерной выборки |
| top\_k | 20 | 20 | Усеченная выборка |
| repeat\_penalty | 1.05 | 1.05 | Штраф за повторения |
| context\_length | 262144 | 262144 | Длинный контекст 128K |
| reasoning | auto | auto | Включение цепочки рассуждений (цепочки мышления) |
| reasoning\_budget | 400 | 400 | Бюджет токенов рассуждения |
| reasoning\_format | deepseek-legacy | deepseek-legacy | Вывод рассуждений в отдельное поле |

> 💡 **Режим мышления**: включается через `--reasoning auto` — модель сначала выполняет внутренние рассуждения, затем выводит ответ. Параметр `reasoning_budget` управляет максимальным количеством токенов мышления (рекомендуется 400, настраивается в диапазоне 100-1000).

## 10. Сравнение форматов квантования

| Формат | Размер | Точность | Описание |
| --- | --- | --- | --- |
| FP16 оригинал | ~54 ГБ | 100% | Без потерь, требует профессиональную видеокарту |
| **MoziSmartBit (данная модель)** | **~13,7 ГБ** | **~99%** | **Собственное интеллектуальное квантование: лучшая точность, минимальный размер** |
| Q4_K_M | ~17 ГБ | ~98% | Стандартный 4-битный GGUF |
| Q5_K_M | ~20 ГБ | ~99% | Более высокая точность |
| Q6_K | ~23 ГБ | ~99,5% | Почти без потерь |
| Q8_0 | ~31 ГБ | ~100% | Без потерь |

> MoziSmartBit, сохраняя точность около 99%, сжимает 27B Dense-модель до 13,7 ГБ (коэффициент сжатия 3,9x), что примерно на 20% меньше, чем Q4_K_M, и лучше подходит для локального развертывания на потребительских видеокартах.

## 11. MTP спекулятивное декодирование (важная функция ускорения)

Данная модель имеет встроенный слой спекулятивного декодирования MTP (Multi-Token Prediction); при его включении скорость инференса увеличивается в **1,5–2 раза**. Это нативная функция архитектуры Qwen3.8, MoziAI сохранил полные веса MTP.

**Принцип**: в архитектуре модели дополнительно обучена легковесная головка предсказания (Draft Model), которая заранее угадывает последующие токены до проверки основной моделью, уменьшая количество forward-проходов и снижая задержку инференса. Ошибки предсказания исправляются основной моделью, что не оказывает негативного влияния на качество вывода.

### Параметры включения

```bash
--spec-type draft-mtp \
--spec-draft-n-max 2 \
--spec-draft-p-min 0.75
```

| Параметр | Рекомендуемое значение | Описание |
| --- | --- | --- |
| --spec-type | draft-mtp | Включение MTP спекулятивного декодирования |
| --spec-draft-n-max | 2 | Максимум 2 предсказываемых токена за раз (рекомендуемое значение, коэффициент принятия около 80%) |
| --spec-draft-p-min | 0.75 | Минимальный порог вероятности принятия (0.0-1.0, чем больше, тем консервативнее) |

### Рекомендации по настройке параметров

| n-max | Коэффициент принятия | Применимые сценарии |
| --- | --- | --- |
| 1 | ~90% | Наиболее консервативно, минимальный прирост скорости |
| **2** | **~80%** | **Рекомендуется: баланс скорости и точности** |
| 3 | ~71% | Универсальные сценарии, заметный прирост скорости |
| 4-5 | ~60-65% | Творческое написание, генерация кода |
| 6 | ~50-55% | Длинный вывод чистого текста (требует настройки p-min) |

> 💡 Чем длиннее контекст, тем больше требуется видеопамяти. При OOM постепенно снижайте параметр `-c`. Используйте `--fit on`, чтобы llama.cpp автоматически подбирал количество слоев под видеопамять. Поддерживаются видеокарты всех брендов: NVIDIA / AMD / Intel.
